# Jim White / ENSESO4Food Call Plan

## Goal Of The Call

Do not pitch hard.

Use the call to learn:

1. Whether messy supplier/shipment data is a real FSMA 204 blocker.
2. Which customer segment feels the pain most.
3. Whether a Dirty Data Audit is complementary to traceability platforms like ENSESO4Food.
4. Who else you should talk to.

## Should You Present A PPT?

No, not for the first call.

Use a simple conversation format.

If you have a sample artifact, keep it ready, but do not lead with it.

Best first-call materials:

- 1-page notes
- 3-line idea summary
- 5-6 discovery questions
- optional sample output if he asks

## Opening

```text
Hi Jim, thanks again for taking the time.

I reached out because I’m trying to understand a narrow part of FSMA 204 readiness: what happens before records are clean enough for traceability software.

I’ve been talking to produce wholesalers/distributors around San Jose. Some are still using paper invoices, handwritten notes, Excel, QuickBooks, or DProduce Man. Larger operators already have traceability systems, but I’m trying to understand where messy supplier records and exceptions still create work.

I’d love to learn from your perspective and see whether this Dirty Data Audit idea is useful, wrong, or already covered by platforms like ENSESO4Food.
```

## Your 30-Second Idea

```text
The idea is a Dirty Data Audit for distributors.

A distributor gives 5-20 redacted shipment record sets: invoice, BOL, label, ASN if available, receiving record.

We return a missing-KDE / mismatch report and a clean Excel or FDA-style export sample.

The question I’m testing is whether messy intake data is a real blocker before traceability software works well.
```

## Main Questions To Ask

1. When small/mid-sized food operators try to become FSMA 204-ready, where do they usually get stuck?
2. Do customers usually have clean digital records, or are paper invoices, PDFs, labels, and Excel still common?
3. Before a traceability platform works, what data does the customer need to already have ready?
4. When lot/source/TLC/KDE fields are missing or conflicting, who fixes it today?
5. Is this usually owned by QA, food safety, receiving, operations, EDI, or supplier compliance?
6. Would a pre-onboarding Dirty Data Audit help customers become ready for platforms like ENSESO4Food?
7. Which segment should I focus on first: produce distributors, seafood importers, processors, restaurants, or small wholesalers?
8. What would make this service credible to the industry?
9. Who else should I talk to?

## What Not To Say Yet

Avoid:

- "I want to partner immediately."
- "Can you use my software?"
- "I will sit in front of ENSESO4Food."
- "AI will automatically fix traceability."
- detailed supplier scorecard roadmap
- exact pricing
- full automation architecture

## If He Asks About Competition

Say:

```text
I’m not trying to replace traceability platforms. I’m trying to understand the messy intake layer before data is ready for those platforms.

If platforms already solve that deeply, I want to learn that. If customers still need cleanup before onboarding, that may be the wedge.
```

## If He Asks What You Have Built

Say:

```text
I’m pre-product right now. I’ve done field discovery and I’m preparing a concierge MVP: take messy invoices/labels/BOLs, manually plus AI-assisted review, and return a clean spreadsheet plus missing-field report.

I don’t want to overbuild before confirming the workflow with people who know the market.
```

## Soft Partnership Question

Ask near the end only if the conversation is positive:

```text
Would it be useful for traceability platforms if someone helped customers clean and structure messy records before onboarding?
```

If he says yes:

```text
Would you be open to me sending a sample Dirty Data Audit output for critique?
```

## Best Closing

```text
This was very helpful.

My next step is to create a small sample Dirty Data Audit output: messy inputs, missing-field report, mismatch summary, and clean export.

Could I send that to you for feedback?

Also, is there one operator, consultant, or distributor you think I should speak with next?
```
