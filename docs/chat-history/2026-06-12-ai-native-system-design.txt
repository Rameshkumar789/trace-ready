3. The system has two modes

Mode A — Audit Mode

This is Jim’s idea.

Purpose:

Tell the company whether its existing system and workflows are FSMA 204-ready.

Audit Mode is periodic.

Examples:

Run once before buying software
Run before an SGS audit
Run before onboarding ReposiTrak / Trakkey / Starfish
Run quarterly to check readiness
Run for each location/site
Run for each supplier group

Output:

“Here are your FSMA 204 gaps and remediation checklist.”

⸻

Mode B — Operations Mode

This is our larger idea.

Purpose:

Continuously resolve traceability exceptions after the audit.

Operations Mode is recurring.

Examples:

Supplier did not send lot code
ASN missing KDEs
Internal lot code overwrote supplier traceability lot code
Transformation not linked to source lot
Customer export missing fields
Supplier repeatedly fails to provide required data

Output:

“Exception detected, routed, followed up, and resolved.”

2. Product Classification Agent

Job

Identify which products are likely covered by FSMA 204.

This is one of Jim’s core audit needs.

Input:

item master
product descriptions
commodity names
pack sizes
supplier names
categories

Output:

Definitely covered
Possibly covered
Not covered
Needs human review

Example output:

Product: Roma tomatoes
Status: Definitely covered
Reason: Fresh tomatoes are on the Food Traceability List.
Product: tomato sauce
Status: Possibly covered
Reason: Needs review because processed form may change applicability.
Product: bananas
Status: Likely not covered
Reason: Not on current Food Traceability List.

This module creates the first major value:

“These are the products you need to worry about.”

⸻

3. Supplier Obligation Agent

Job

Map covered products to suppliers.

Jim emphasized:

Once you know covered products, you need to know which suppliers must send required information.

Input:

covered product list
supplier list
purchase records
receiving records
broker records
item-supplier mapping

Output:

covered product → supplier → required KDE responsibility

Example:

Roma tomatoes → Supplier: Taylor Boys
Required supplier info: harvest KDEs, traceability lot code, source reference
Fresh basil → Supplier: Craigmore Farm
Required supplier info: harvest/pack/shipping KDEs
IQF strawberries → Supplier: Frozen Fruit Co.
Required supplier info: depends on processing/transformation history

This becomes a supplier outreach list.

5. Lot-Code Lineage Agent

Job

Check whether the traceability lot code is preserved correctly.

This is one of Jim’s most important insights.

Rule:

If you receive a traceability lot code and do not transform the product, you should preserve that lot code through shipping. If you transform the product, you may create a new lot code but must link it to the source lot.

Input:

incoming lot code
internal lot code
outgoing lot code
transformation records
receiving records
shipping records

Output:

preserved correctly
overwritten incorrectly
transformation linkage present
transformation linkage missing
cannot determine

Example:

Incoming supplier lot: TOM-2026-0421-A
Internal lot assigned: WH-99881
Transformation: None
Outgoing shipment uses: WH-99881
Risk: Red
Reason: Supplier traceability lot code appears overwritten without transformation.

This is a very strong audit finding.

⸻

6. Transformation Linkage Agent

Job

Check whether input lots are linked to output lots during transformation.

Important for:

packers
processors
food hubs
commercial kitchens
fresh-cut produce
repackers
commissaries

Input:

input product lots
transformation activity
output product lots
recipe/work order
production batch
pack date
output quantity

Output:

input-output linkage present
missing source lot
missing output lot
quantity mismatch
transformation record incomplete

Example:

Input: bulk tomatoes lot TOM-01
Output: clamshell tomatoes lot CLAM-77
Transformation record: missing input lot linkage
Risk: Red
Reason: Output lot cannot be traced back to source lot.

9. Remediation Agent

Job

Turn gaps into concrete next steps.

Example output:

1. Classify 14 uncertain products against Food Traceability List.
2. Ask 7 suppliers to start sending traceability lot code source/reference.
3. Stop overwriting incoming traceability lot codes for non-transformed products.
4. Add input-output lot linkage to transformation workflow.
5. Add source reference field to receiving template.
6. Create outbound traceability export for customers.
7. Train receiving staff to capture lot code from case labels.

This is critical because the audit should not just say:

“You are noncompliant.”

It should say:

“Here is exactly what to fix.”

7. What should be AI vs rules?

Rules should handle

Required KDE checklist
Red/yellow/green scoring
date normalization
quantity/unit normalization
reference document tracking
product-supplier mapping
field presence checks
lot-code comparison
transformation input-output linkage checks

AI should handle

messy product description classification
Food Traceability List interpretation support
document type recognition
field extraction from PDFs/images
matching supplier product descriptions to item master
explaining gaps in plain English
drafting supplier follow-up emails
generating remediation checklist language

Human should handle

borderline product classification
compliance-sensitive decisions
uncertain lot-code lineage
supplier disputes
final audit approval

This keeps cost low and trust high.
